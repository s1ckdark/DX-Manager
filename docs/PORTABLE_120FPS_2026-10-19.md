## Implemented behavior

-30/60/120 choices; default60, localized `120 (Experimental)` / `120 (실험적)`.
- Selecting120 shows no popup. Each actual120 start uses one themed warning,
  defaulting to Cancel. Saved settings, DeX, all three slots, tray/automatic
  launches and apply-settings restarts use the same UI gate. Missing consent
  also blocks at the service layer before device I/O or stopping an old window.
- Warnings cover keeping the phone screen on, heat/battery increase, permanent
  OLED burn-in, avoiding prolonged/unattended use, overheating and variable FPS.
  No skip-warning option, input injection or forced refresh-rate setting.
- Capture physical context, transport, service and deep-copied run settings
  before confirmation/delays. A UI selection change never redirects the launch.
- Nullable `TurnScreenOffBeforeHighFps` persists the prior true/false value in
  defaults, phone DeX, slots and app profiles, including clone/load/projection.
  At120 the screen-off toggle is off/disabled;30/60 restores the exact value and
  clears the backup. Legacy120 with no backup restores documented defaulttrue.
- Actual live process FPS, rather than newly edited settings, decides whether
  a phone requires its screen on. A120 DeX or app-slot process suppresses other
  starts and delayed screen-off requests on that physical phone. The last120
  exit lets existing ordinary requests resume. Other phones are independent.
- Builders omit `-S`/`--turn-screen-off`/`--no-power-on` at120. Reserved advanced
  `--max-fps` (including abbreviations) prevents bypass. Screen-on state is
  published inside the short process-start gate; window waits stay outside it.
- Local EN/KO release notes appear once per version increase for existing users,
  after safety consent and before device startup. Old consent is read before any
  new safety acknowledgement. A settings file alone never identifies an upgrade.
  Fresh installations skip these notes and save the current baseline.
- `config/update-notice.json` is independent of settings reset and daily online
  update checks. Atomic writes never lower the checkpoint on downgrade. Failed
  saves/abnormal dismissal remain retryable. Informational note errors do not
  block startup; mandatory120 consent errors do block a start.

## Verification boundaries

`scripts/Verify-OfficialBuild.ps1` builds the actual .NET Framework4.6.2 x64 app
and runs existing and new assembly/UI checks. New checks cover JSON round trips,
exact true/false restoration, app-profile/slot UI projection, cancel-default
warnings in EN/KO/light/dark, actual canceled starts for DeX/slots1–3, fail-closed
service calls, argument overrides, both kinds of live120 process and phone
isolation, old/fresh/downgrade/malformed/write-failure notice history, plus actual
local note dialogs/version placeholders.

Test processes use no real ADB/device session. Their generated state and mock UI
captures are internal test evidence, not real-phone documentation screenshots.
The new EXE/ZIP require the maintainer's fresh antivirus scan. Real phone120 FPS,
Windows7, GPU/firmware-specific FPS and DPI combinations remain user verification.
Screenshots/public-source dependency closure and remote macOS preservation remain
separate publication preparation items; preparing the ZIP does not publish it.
