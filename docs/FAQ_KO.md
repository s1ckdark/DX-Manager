## Q1. 휴대폰에 작은 화면(보조 디스플레이)이 남아 있습니다.

DX Manager가 강제 종료되었거나, 정리 명령을 보내기 전에 USB 또는 무선
연결이 완전히 끊기면 Android의 가상 디스플레이 설정이 남을 수 있습니다.
정상적으로 DX Manager를 종료하면 프로그램이 이 설정을 자동으로
제거합니다.

정상 종료할 때는 휴대폰을 연결한 상태에서 **DeX 중지**를 누르거나
`Left Alt+F8`을 누르거나, 시스템 트레이의 DX Manager 아이콘을 마우스 오른쪽
버튼으로 눌러 **종료**를 선택하십시오. 정리가 끝난 뒤 연결을 해제하십시오.

화면이 계속 남아 있다면 휴대폰에서 다음 순서로 제거할 수 있습니다.

1. **개발자 옵션**을 엽니다.
2. **보조 디스플레이 시뮬레이션(Simulate secondary displays)**을
   선택합니다.
3. 이미 **없음**이 선택되어 있어도 아무 해상도나 한 번 선택합니다.
4. **보조 디스플레이 시뮬레이션**을 다시 열어 **없음(None)**을 선택합니다.

처음부터 **없음**만 선택하면 남은 화면이 지워지지 않을 수 있습니다. 해상도를
한 번 선택한 뒤 **없음**으로 바꾸면 Android가 overlay 설정을 새로 반영하고
남아 있던 가상 화면이 제거됩니다.

번들 공식 **DX Companion**을 설치하고 DX Manager의 **설정 > 진단 > DX
Companion**에서 검증과 권한 부여를 마쳤다면, 앱 본체나
빠른 설정 타일·홈 화면 위젯에서도 남은 화면을 제거할 수 있습니다. 비정상
종료 뒤 남은 개발자 옵션의 **절전모드 해제**도 끌 수 있습니다. 자세한
설치와 사용 방법은 [한국어 사용 설명서](USER_GUIDE_KO.md#12-선택형-dx-companion)를
참조하십시오.

## Q2. 삼성 브라우저를 자동 실행할 때 선택 앱 강제 종료를 사용하는 이유는 무엇인가요?

삼성 브라우저가 휴대폰 화면에서 실행 중인 상태로 DeX 화면에 다시 열리면,
일부 환경에서 한영키 전환이 동작하지 않는 경우가 있습니다. **선택 앱 강제
종료**를 켜면 기존 삼성 브라우저 프로세스를 휴대폰에서 먼저 종료한 뒤 DeX
화면에서 새로 실행하므로 이 문제를 피할 수 있습니다.

이 기능은 브라우저 데이터나 북마크를 삭제하지는 않지만, 저장하지 않은
입력 내용이나 진행 중인 작업은 사라질 수 있습니다. 다른 앱에서는 필요할
때만 사용하십시오.

## Q3. 휴대폰을 두 대 이상 연결하면 어떤 기기를 사용하나요?

기기 선택기에서 대상 휴대폰을 선택합니다. 휴대폰마다 DeX·단일창 세 슬롯, 앱 프로필, 연결 환경과
전송 상태를 따로 관리하며, 탭을 바꿔도 다른 휴대폰의 세션은 유지합니다. 같은 휴대폰의 USB와 Wi-Fi는
하나의 항목으로 합칩니다.

배지는 실제 USB·Wi-Fi·동시 연결을 표시합니다. 새 실행은 승인된 USB가 있으면 우선 사용하고, 없으면
승인된 무선 연결을 사용할 수 있습니다. 실행 중인 창은 시작한 serial을 유지하며 다른 연결로 옮기지
않습니다. 휴대폰→PC 파일은 수신 폴더 아래 휴대폰 이름별 하위 폴더에 저장합니다.

## Q4. 1600×900보다 낮은 해상도에서 DeX 화면 일부가 잘립니다.

Samsung DeX의 기본 최소 해상도는 1600×900입니다. DX Manager에서는 더
낮은 가상 해상도도 만들 수 있지만, 앱 서랍 상단이 잘리는 등 일부 DeX UI가
작은 화면에 맞게 배치되지 않을 수 있습니다.

앱 실행 자체에는 문제가 없을 수 있으나 전체 DeX UI를 정상적으로 사용하려면
1600×900 이상의 해상도를 권장합니다. 이 현상은 낮은 해상도에 대한 Samsung
DeX UI 제약이며 DX Manager가 화면 일부를 잘라내는 것은 아닙니다.

## Q5. 해상도나 DPI를 바꾸니 바탕화면 아이콘과 배경화면이 달라졌습니다.

Samsung DeX는 해상도와 DPI 조합에 따라 화면 배율과 레이아웃 프로필을 다르게
판정할 수 있습니다. 같은 해상도에서도 DPI가 달라지면 아이콘 크기, 위젯
배치, 편집 가능 상태가 달라질 수 있으며 배경화면도 별도 상태로 관리될 수
있습니다.

따라서 설정을 바꾼 뒤 이전과 다른 바탕화면이 표시되어도 가상 디스플레이를
잘못 선택한 것은 아닐 수 있습니다. 자주 사용할 해상도와 DPI 조합을 정한
뒤 그 조합에서 바탕화면을 구성하는 것이 가장 안정적입니다.

## Q6. 최근 앱 화면이 비정상적으로 보이고 데스크톱 1로 돌아갈 수 없습니다.

일부 해상도/DPI 조합에서는 DeX를 처음 실행한 뒤 최근 앱 화면의 데스크톱
표시가 어긋날 수 있습니다. 다음 방법으로 복구할 수 있습니다.

1. 최근 앱 화면에서 모니터 그림 안의 **+** 버튼을 눌러 새 데스크톱을
   만듭니다.
2. 화면 왼쪽에 일부 보이는 **데스크톱 1**을 선택합니다.

정상 화면으로 돌아오면 같은 DeX 세션에서는 대체로 다시 발생하지 않습니다.
Samsung 펌웨어나 One UI 버전에 따라 화면 구성과 명칭은 달라질 수 있습니다.

## Q7. DPI를 120보다 낮게 설정할 수 없는 이유는 무엇인가요?

확인된 Samsung DeX 환경에서는 DPI 120이 가상 디스플레이를 생성할 수 있는
최솟값입니다. 119 이하에서는 overlay가 만들어지지 않아 새 display ID를
찾을 수 없습니다.

DX Manager는 120보다 작은 값이 입력되면 편집 전 값으로 되돌리고
안내합니다. 반대로 매우 높은 DPI는 생성되더라도 글자와 UI가 지나치게
커져 사용하기 어려울 수 있습니다.

## Q8. 로그의 scrcpy-server 전송 속도가 평소보다 낮게 표시됩니다.

다음과 같은 줄은 scrcpy가 작은 `scrcpy-server` 파일을 휴대폰으로 전송할
때 계산한 순간 속도입니다.

```text
scrcpy-server: 1 file pushed, 0 skipped. 42.9 MB/s
```

파일이 작고 전송 시간이 매우 짧아 수치 변동이 크며, 이 값이 USB 링크의
정확한 속도나 이후 영상 스트리밍 속도를 의미하지는 않습니다. 낮은 숫자만
표시됐다고 연결 오류로 판단할 필요는 없습니다.

다만 DeX 화면까지 버벅이거나 직접 scrcpy를 실행해도 계속 낮게 나온다면
데이터 전송을 지원하는 다른 USB 케이블과 PC의 다른 USB 포트를 시험해
보십시오. 충전 위주 케이블이나 품질이 낮은 케이블이 원인일 수 있습니다.

## Q9. 무선 ADB 연결 또는 자동 재연결이 실패합니다.

다음 항목을 순서대로 확인하십시오.

- PC와 휴대폰이 서로 직접 통신할 수 있는 같은 로컬 네트워크인지 확인
- 게스트 Wi-Fi, AP/클라이언트 격리, VLAN과 회사 방화벽 확인
- 페어링 포트와 실제 연결 포트를 혼동하지 않았는지 확인
- 휴대폰 IP 주소가 바뀌지 않았는지 확인
- mDNS 자동 검색이 차단되면 페어링 포트가 아니라 무선 디버깅 화면의 현재
  연결 포트를 수동 입력
- 휴대폰 재부팅 후 USB로 무선 연결 준비를 다시 실행
- Android 11 이상 무선 디버깅은 필요하면 다시 페어링

무선 주소가 `adb devices`에 보이더라도 `offline`이면 연결을 끊었다가 다시
연결하십시오. 같은 Wi-Fi 이름을 사용한다는 사실만으로 기기 간 통신이
보장되지는 않습니다.

## Q10. 장치 상태가 unauthorized 또는 offline으로 표시됩니다.

`unauthorized`는 PC의 ADB 키가 아직 휴대폰에서 승인되지 않았다는 뜻입니다.
휴대폰 화면을 켜고 RSA 디버깅 허용 창을 승인하십시오. 창이 나타나지 않으면
USB 디버깅 승인을 취소한 뒤 케이블을 다시 연결하거나 USB 디버깅을 껐다가
켜 보십시오.

`offline`은 장치 항목은 있지만 ADB 명령을 받을 수 없는 상태입니다. 케이블,
USB 포트, 무선 네트워크를 확인하고 연결을 다시 시도하십시오. USB 장치가
계속 나타나지 않으면 Samsung USB 드라이버와 **보안 위험 자동 차단** 설정도
확인하십시오.

## Q11. 오른쪽 Shift를 왼쪽 Shift로 보정하는 이유는 무엇인가요?

Windows용 scrcpy 4.0/SDL3에서 Windows가 물리 오른쪽 Shift 입력을 정상적으로
감지해도 Android로 전달되지 않는 현상을 재현했습니다. scrcpy
3.3.4/SDL2에서는 같은 문제가 발생하지 않았습니다.

DX Manager는 번들 5.0.1을 포함한 SDL3 기반 scrcpy 클라이언트와의 호환을 위해 해당 scrcpy
창이 활성화된 동안에만 오른쪽 Shift 입력을 왼쪽 Shift로 바꿔 전달합니다.
일반적인 Shift 입력은 사용할 수 있지만 해당 세션의 Android 앱은 좌우
Shift를 구분할 수 없습니다. 다른 Windows 앱과 SDL2 기반 scrcpy에는 이
보정이 적용되지 않습니다.

## Q12. 기기 연결 후 시작 대기와 프로세스 제한시간은 무엇이 다른가요?

**기기 연결 후 시작 대기**는 휴대폰 연결 상태와 기기 이름을 확인한 뒤,
DeX 또는 단일창의 실제 시작 명령을 보내기 전에 의도적으로 기다리는
시간입니다. 범위는 0~60초이고 기본값은 1초입니다. 0으로 설정하면 연결 확인
후 곧바로 시작합니다.

**프로세스 제한시간**은 ADB나 scrcpy 보조 프로세스가 응답하거나 창을 만들
때까지 기다릴 수 있는 최대 시간입니다. 명령이 정상적으로 빨리 끝나면 제한
시간 전체를 기다리지 않습니다. 느린 PC나 장치에서 시간 초과가 반복되는
경우가 아니라면 고급 옵션의 기본값을 바꿀 필요가 없습니다. 관리형 드래그 앤
드롭 파일 전송 전체에는 이 시간이 적용되지 않으며, 대용량 ADB push는 완료,
실패, 취소 또는 세션 종료까지 계속됩니다.

시작 대기 시간은 **설정 > 일반 > 기기 연결 시 DeX 자동 실행**에 있습니다. 다른 제한시간 값은 저장되는 설정이며 현재 진단 화면에 모두 개별 옵션으로 표시되는 것은 아닙니다.

## Q13. 사용 중 USB 연결이 갑자기 끊기면 어떻게 처리되나요?

그 USB 연결을 사용하던 창을 중지하고 가능한 정리를 시도합니다. 휴대폰이 이미 응답하지 않으면
가상화면·화면 전원 설정이 복구됐는지 PC에서 확인할 수 없습니다. Wi-Fi가 남아 있다고 해당 창을 자동으로
옮기거나 다시 실행하지 않습니다.

다시 연결하세요. 실제 재연결 때는 저장된 DeX 자동 실행 설정이 적용될 수 있으며, 그 외에는 직접 시작합니다.
검증된 Companion이 설치돼 있으면 설정된 보조 복구를 사용할 수 있습니다. 수동 복구는 Q1,
2.1.6의 세션 보호 알림은 Q26을 참고하세요.

## Q14. 휴대폰 화면 끄기와 잠자기 방지는 어떻게 다른가요?

**폰 화면 끄기 (`-S`)**는 scrcpy 세션을 실행하는 동안 실제 휴대폰 패널을
끄는 기능입니다. 휴대폰 화면이 꺼져도 DeX 가상 화면과 scrcpy 영상은 계속
동작합니다.

**잠자기 방지**는 세션 사용 중 Android가 잠들거나 연결을 중단하지 않도록
활성 상태를 유지합니다. 여러 DeX/단일창 세션 중 하나라도 화면 끄기 또는
잠자기 방지를 요청하면 DX Manager가 전체 세션 상태를 기준으로 관리합니다.
모든 관련 세션을 종료하거나 DX Manager를 정상 종료하면 휴대폰 화면과
stay-awake 상태의 복구를 시도합니다.

실험적120 FPS에서는 화면 끄기를 자동 해제합니다.30/60으로 돌아오면 이전 값을 복원하며 [Q30](#q30-120-fps에서-폰-화면-끄기가-비활성화되는-이유는-무엇인가요)을 참고하세요.

## Q15. 휴대폰을 충전할 때 화면이 계속 켜져 있습니다.

DX Manager가 DeX 또는 단일창 사용 중 적용한 **잠자기 방지 (`-w`)** 설정은
세션이나 프로그램을 정상 종료하면 원래 상태로 복원됩니다.

다만 휴대폰 연결이 끊어진 상태에서 DX Manager를 종료했거나 프로그램이
비정상 종료된 경우에는 ADB 명령을 보낼 수 없어 설정을 복원하지 못할 수
있습니다. 이때는 다음 중 한 가지 방법으로 복구하십시오.

- 휴대폰의 **개발자 옵션 → 절전모드 해제** 항목을 직접 끕니다.
- 같은 휴대폰을 DX Manager에 다시 연결한 뒤 정상적인 방법으로 종료합니다.

이 설정은 USB 또는 충전기에 연결했을 때 화면이 자동으로 꺼지지 않게 할 수
있습니다.

## Q16. Windows 7에서 무엇이 필요하며, DXManager.exe만 복사하면 왜 안 되나요?

DX Manager는 64비트 Windows 7 SP1과 .NET Framework 4.6.2 이상을
지원합니다. 32비트 Windows는 지원하지 않습니다. Windows 7/8.1에서는 번들
레거시 ADB 실행에 필요한 Universal CRT 업데이트와 Samsung USB 드라이버가
필요할 수 있습니다.

.NET Framework 4.6.2는 Windows 7 SP1에 기본 포함된 구성 요소가 아닙니다.
Windows 7 SP1 및 오프라인·폐쇄망 PC와의 호환성을 유지하기 위해 선택한 최소
대상 버전입니다. 설치되어 있지 않다면 [Microsoft 공식 다운로드
페이지](https://dotnet.microsoft.com/en-us/download/dotnet-framework/net462)에서
런타임을 받으십시오. 같은 페이지의 오프라인 설치 파일을 다른 컴퓨터에서
받아 대상 PC로 옮겨 설치할 수도 있습니다.

.NET Framework 4.x는 제자리 업데이트 방식입니다. 4.7.2 또는 4.8이 이미
설치되어 있다면 4.6.2로 낮추거나 함께 설치하려고 할 필요가 없습니다. 같은
DX Manager 빌드가 설치된 최신 4.x 런타임에서 실행됩니다.

`DXManager.exe`는 다음 파일을 함께 사용하므로 실행 파일만 따로 복사하면
정상적으로 동작하지 않습니다.

- `tools` 아래 ADB와 scrcpy 실행 파일
- `tools/adb-proxy` 아래 DX Manager ADB 파일 전송 도우미
- scrcpy DLL과 `scrcpy-server`
- 한국어 리소스와 설정 파일
- 라이선스 및 제3자 고지 파일

배포 ZIP의 폴더 구조를 그대로 유지하고, 설정·로그·스크린샷을 저장할 수
있는 쓰기 가능한 위치에서 실행하십시오.

## Q17. 드래그 앤 드롭 파일 전송은 어떻게 동작하며 끌 수도 있나요?


실행 중인 DeX·단일창 scrcpy에 파일이나 폴더를 놓습니다. 기본 관리형 전송은 Unicode 이름,
폴더 구조·빈 폴더를 보존하며 동명 파일은 번호를 붙여 기존 항목을 덮어쓰지 않습니다.
독립 전송창은 진행·대기·완료·실패를 표시하며 정확하지 않은 백분율·남은 시간을 만들지 않습니다.

대상 폴더는 **설정 > 경로 > PC → 휴대폰 파일 전송**에서 바꾸고 새 scrcpy 창부터 적용합니다.
현재 설정 화면에는 별도의 관리형 모드 스위치가 없습니다. 고급 설정으로 끄려면 완전히 종료한 뒤
`config/settings.json`을 백업하고 `Features.ManagedFileTransferEnabled`를 `false`로 바꾸세요.
프로그램과 scrcpy 창을 다시 열면 순정 파일 드롭을 사용합니다. 단독 APK 설치 동작은 유지합니다.

## Q18. 이전 One UI 버전에서 DeX 창이 검게 표시됩니다.

현재 정상 동작을 확인한 기준은 Android 16 / One UI 8.x가 설치된 DeX 지원
Galaxy 기기입니다. One UI 7.x 이하에서는 DX Manager의 가상 디스플레이
방식을 원활하게 사용할 수 있는지 확인되지 않았으며 검은 DeX 창이 열릴 수
있습니다. 기기 모델, Samsung 펌웨어와 예전 클래식 DeX 구현 사용 여부에 따라
동작이 달라질 수 있습니다.

단일창은 scrcpy 자체 가상 디스플레이를 사용하므로 동작할 수 있지만 펌웨어에
따라 입력 지원이 다를 수 있습니다. HID 키보드나 HID 마우스 사용 시 불안정한
경우 해당 옵션을 끄고 다시 시험할 수 있습니다. 이 방법이 해당 기기나 One UI
버전의 지원을 보장하는 것은 아닙니다.

## Q19. ADB 버전이 항상 1.0.41로 보였는데 실제 사용 버전은 무엇인가요?

`Android Debug Bridge version 1.0.41`은 여러 platform-tools 릴리스가 공통으로
출력하는 ADB 프로토콜 문구이며 실제 실행 파일의 빌드 버전이 아닙니다.

DX Manager 1.1.0 이상은 그 다음 `Version ...` 줄을 읽습니다. 번들 scrcpy ADB는
`37.0.1-15733141`, Windows 7/8.1용 레거시 ADB는 `34.0.1-9979309`로
표시됩니다. 수동으로 ADB를 선택하면 해당 실행 파일의 `Version ...` 값이
표시됩니다.

## Q20. 금융·게임 앱이 실행되지 않거나 화면이 검게 표시됩니다.

일부 금융·게임·스트리밍·보안 앱은 USB 디버깅이나 개발자 옵션이 켜진 환경을
감지해 실행을 거부할 수 있습니다. 보안 화면 또는 DRM 콘텐츠의 캡처·미러링을
차단하거나 가상·보조 디스플레이에서의 실행을 허용하지 않는 앱도 있습니다.

이는 해당 앱과 Android의 보안 정책에 따른 동작입니다. DX Manager는 이러한
보안 제한을 우회하지 않습니다.

## Q21. DeX에서 실행한 앱이 휴대폰 화면에서 열립니다.

일부 앱은 다중 디스플레이를 완전히 지원하지 않거나 휴대폰에서 이미 실행 중인
인스턴스를 다시 사용합니다. 휴대폰에서 해당 앱을 완전히 종료한 뒤 DeX에서
다시 실행하거나 DX Manager의 **선택 앱 강제 종료** 옵션을 사용해 보십시오.

그래도 휴대폰에서 열린다면 해당 앱이 보조 디스플레이 실행을 제대로 지원하지
않는 경우일 수 있으며 DX Manager에서 강제로 변경하지 못할 수 있습니다.

## Q22. 마우스가 DeX 창 밖으로 나오지 않습니다.

**HID 마우스 (`-M`)**를 켜면 scrcpy가 마우스를 Android에 직접 연결된 입력
장치처럼 전달하므로 포인터가 scrcpy 창에 캡처됩니다. 왼쪽 `Alt`를 눌러 캡처를
일시적으로 해제하거나 다시 활성화할 수 있습니다.

Windows와 DeX 사이에서 포인터를 항상 자유롭게 이동하려면 HID 마우스를 끄고
DeX 또는 단일창을 다시 여십시오. 이 경우 마우스가 일반 하드웨어 마우스가
아닌 터치 입력에 가깝게 동작하므로, 측면 버튼이 최근 앱을 열거나 왼쪽 버튼을
길게 누르는 동작이 화면 롱터치로 처리되는 등 조작 방식이 달라질 수 있습니다.

## Q23. Companion 메뉴의 정리 권한 부여 버튼이 비활성화되어 있습니다.

**설정 > Companion**에서 대상 휴대폰을 고르고 상태를 새로고침하세요. 설치와 정리 권한은 진단 메뉴가
아닌 이 전용 페이지에서 관리합니다.

USB 또는 무선 ADB로 승인된 기기여야 하며, 번들과 설치 앱의 패키지·지원 버전·APK 해시·공식 서명을
검증합니다. 앱이 없거나 변조됐거나 지원 버전보다 오래됐거나 서명이 다르면 정리 권한을 주지 않습니다.
표시된 이유를 확인하고 필요한 경우 번들 **Companion 2.1.6**으로 설치/업데이트하세요.

정리 권한은 `WRITE_SECURE_SETTINGS`이며 Companion에서 가상화면·절전모드 해제 제어에 사용합니다.
같은 서명으로 업데이트하거나 재부팅하면 일반적으로 유지되고 삭제하면 사라집니다.
정리 권한 상태와 파일 전송 준비 상태는 다르므로, 정리 권한 부여 실패만으로 전송 연결 실패를 뜻하지는 않습니다.

## Q24. DX Companion에서 파일 또는 폴더를 PC로 보낼 수 없습니다.

DX Manager를 실행해 대상 휴대폰을 연결하고 **설정 > Companion**에서 공식 **2.1.6**으로 업데이트하세요.
**설정 > 경로 > 휴대폰 → PC 파일 전송**을 켜고 **PC 수신 폴더**를 선택한 뒤 Companion 전송 화면의
수신 준비 상태를 확인합니다.

일반 파일은 갤러리·내 파일 > 공유 > **DX Manager로 보내기**, 폴더는 Companion의 폴더 선택 기능을
사용합니다. 비슷한 공유 항목이 여럿이면 이 PC에 연결된 정식 Companion을 선택하세요. 별도 테스트 앱이나
오래된 다른 앱을 고르면 정식 Companion과 통신 상태가 다를 수 있습니다.

PC 미실행·연결 해제·수신 꺼짐·미검증/구버전 앱에서는 전송할 수 없습니다. 실패하면 다시 연결해 새로
시작하세요. 같은 이름은 번호로 분리하고 하위 구조·빈 폴더를 보존합니다. PC 전송창은 항목·개수를 표시하며
부정확한 퍼센트나 남은 시간을 만들지 않습니다. PC 수신 폴더 아래 휴대폰 이름별 하위 폴더도 확인하세요.

## Q25. 인터넷이 없을 때 업데이트 확인은 어떻게 동작하나요?

로컬 날짜 기준 매일 첫 실행에 한 번 백그라운드에서 확인하고 전체 요청에5초 제한을 둡니다.
실패도 당일 시도로 저장하므로 오프라인에서 다시 실행해도 반복 재시도하지 않습니다.
로컬 USB·LAN 사용을 막거나 최신 버전·오프라인 결과창을 자동으로 띄우지 않습니다.

수동 결과창은 제3자 라이선스 옆의 **설정 > 정보 > 업데이트 확인**으로 엽니다.
자동으로 새 버전을 찾으면 오른쪽 아래 비모달 배너 또는 트레이 알림을 사용합니다.
X로 해당 버전 안내를 닫으며 GitHub 버튼은 페이지를 열고 배너는 남깁니다.
전에 발견한 새 버전 배너는 오프라인에서도 표시될 수 있고 다운로드·설치는 직접 진행합니다.

## Q26. Companion의 세션 보호 알림이 남아 있습니다.

인증된 PC 연결을 감시하므로 DX Manager가 휴대폰을 인식하기만 해도 표시될 수 있습니다.
DeX 실행 전이나 PC와 정상 연결 중에 알림이 있는 것은 정상입니다.

Companion을 **2.1.6**으로 업데이트하세요. PC 연결 끊김이 확인되고 가상화면·잠자기 방지가 모두
해제됐음을 검증하면 복구 타이머를 기다리지 않고 감시와 알림을 종료합니다. 새 연결에는 짧은 초기
확인 시간을 둡니다. 복구할 설정이 남거나 상태 확인이 안 되면 기존 연결 해제 복구 정책을 유지합니다.
PC 소켓만 끊기고 설정된 USB·Wi-Fi 연결이 계속 있다고 보이는 경우는 연결 자체가 제거된 경우와 다릅니다.

## Q27. 첫 실행 동의창이 매번 나오나요?

아닙니다. 새 배포본에서는 확인란을 체크하고 동의를 저장할 때까지 표시합니다.
거절하면 동의하지 않고 종료하며 확인란을 체크하지 않은 상태의 Enter로 동의되지 않습니다.
이후 실행은 `config/onboarding.json`을 따릅니다. `config/settings.json`과 별도로 저장하므로
설정 초기화로도 동의 기록은 유지합니다. 기록 없는 새 폴더·손상된 상태·저장할 수 없는 위치에서는
다시 표시될 수 있으니 쓰기 가능한 위치를 사용하세요.

동의는 포터블 config 폴더에 저장됩니다. 새 버전 폴더로 옮길 때 그 이력을 함께 복사해야 유지되며, 깨끗한 새 폴더는 새 설치 상태입니다.

## Q28. 하드웨어 디코딩이 실제로 켜졌는지 어떻게 확인하나요?

번들 scrcpy **5.0.1**의 DeX·단일창 세 슬롯에는 `--hwdec=auto`를 넣습니다.
실제 선택은 OS·GPU·드라이버에 따라 달라 모든 PC에서 하드웨어 디코딩을 보장하는 것은 아닙니다.
CPU 사용량만 보지 말고 scrcpy 로그의 **Video decoding: d3d11va** 같은 출력을 확인하세요.
Windows 7에서는 최신 Windows와 다른 디코더가 선택될 수 있습니다.

**설정 > 진단 > 환경 검사**에서 선택된 scrcpy의 전체 버전을 확인할 수 있습니다.
고급 인자에 `--hwdec`를 직접 지정한 경우 그 값을 유지하며 중복 추가하지 않습니다.

## Q29. Enter와 Shift+Enter 전환은 어떻게 동작하나요?

공개2.5.0은 **설정 > 입력**의 선택형 **Scroll Lock** 전환을 유지합니다.
꺼두면 일반 Enter는 그대로 전달되고, 켜면 대상 scrcpy 창이 활성화된 동안 설정과 Scroll Lock 상태에
따라 변환합니다. 앱별 AI 입력 동작을 자동으로 감지하는 규칙은 포함하지 않습니다.
Enter가 반대로 동작한다면 이 옵션과 Scroll Lock 상태를 먼저 확인하세요.


## Q30. 120 FPS에서 폰 화면 끄기가 비활성화되는 이유는 무엇인가요?

120 FPS는 **실험적 최대값**이며 기본값은 60 FPS입니다. 휴대폰 화면을 켜두어야 합니다.
120을 선택할 때 팝업은 없고, **실제 120 FPS 실행마다** 경고를 확인합니다.
DeX·단일창 세 슬롯, 저장된 설정, 트레이·자동 실행, 설정 적용 재실행도 같습니다.
기본 동작은 취소이며 취소하면 시작하지 않습니다.

발열·배터리 소모가 증가하고 OLED 화면에 고정 이미지를 오래 표시하면 영구 번인이 생길 수 있습니다.
장시간 사용하거나 켜둔 채 방치하지 말고 과열되면 중단하세요.
입력을 자동 주입하거나 Android 주사율 설정을 강제하는 기능은 아닙니다.

30/60으로 돌아오면 이전 화면 끄기 true/false를 정확히 복원합니다.
기기·모드·앱 프로필별로 보존하며, 같은 폰에 120 FPS 세션이 하나라도 있으면
다른 세션의 화면 끄기를 마지막 120 세션 종료까지 보류합니다. 다른 휴대폰은 독립적입니다.

## Q31. 실제 FPS가 120보다 낮은 이유는 무엇인가요?

설정은 상한이며 항상 120 프레임을 보장하지 않습니다.
기기·앱·입력 활동, 렌더링·인코딩·디코딩 성능과 연결 상태 등에 따라 달라지고
화면 변화가 적으면 전송 프레임도 줄어들 수 있습니다.
휴대폰 패널을 켜두어야 하며 직접 끄면 FPS가 낮아질 수도 있습니다.
이득이 없거나 폰이 뜨거워지면 30/60 FPS를 사용하세요.

고급 인자의 `--max-fps`로 이 제한을 덮어쓸 수 없으며 실행 경고·화면 규칙을 일관되게 적용합니다.

## Q32. 업데이트 후 변경사항 팝업은 무엇인가요?

로컬 변경사항 안내이며 하루 한 번 온라인 업데이트 확인, 필수 안전 동의·120 FPS 경고와 별개입니다.
인터넷을 쓰지 않고 `config/update-notice.json`에 확인한 버전을 기록합니다.

이전 안전 동의 기록이 있는 설치에서는 아직 확인하지 않은 새 버전의 안내를,
안전 동의 후·기기 초기화와 자동 실행 전에 한 번 표시합니다.
새 폴더나 이전 동의 기록이 없는 설치는 안전 안내를 표시하고 현재 버전을 기준으로 기록합니다.
확인 버튼을 누르면 완료 처리하고, 닫기·취소·저장 실패 시 다시 나올 수 있습니다.
설정 초기화와는 별개이며 낮은 버전을 실행해도 기록을 낮추지 않습니다.

## Q33. ZIP 파일 이름에서 버전이 빠진 이유는 무엇인가요?

Windows 2.5.0부터 ZIP 이름은 **`DX-Manager-win-x64.zip`**으로 고정하고
내부 폴더를 **`DX Manager v2.5.0`**처럼 버전으로 구분합니다.
EXE만 꺼내지 말고 내부 폴더 전체를 풀어 사용하세요.

[최신 릴리스](https://github.com/maze-mei/DX-Manager/releases/latest) 또는
[최신 Windows 고정 다운로드](https://github.com/maze-mei/DX-Manager/releases/latest/download/DX-Manager-win-x64.zip)를 사용합니다.
최신 릴리스에 정확히 같은 이름의 파일이 있어야 직접 다운로드할 수 있습니다.
예전 태그·파일명이 들어간 고정 URL이 자동으로 새 버전으로 바뀌지는 않으며 외부 서버의 사본도 오래될 수 있습니다.

## Q34. 업데이트할 때 설정을 유지하려면 어떻게 하며 2.0.1에서는 왜 알림이 없나요?

2.0.1까지의 기존 프로그램에는 업데이트 확인 기능이 없습니다. 공식 릴리스에서 새 버전을 직접 받으세요.

기존 프로그램을 완전히 종료하고 휴대폰 정리가 끝난 뒤 새 ZIP을 풉니다.
두 프로그램이 꺼진 상태에서 개인 **config** 폴더를 새 버전 폴더로 복사하면 설정과 동의·안내 이력을 유지할 수 있습니다.
필요한 캡처·로그·수신 파일은 별도로 보관하고 이런 개인 파일은 공개 업로드에 포함하지 마세요.
동의 기록이 없는 깨끗한 폴더에서는 첫 실행 안전 안내가 다시 나옵니다.

[기존 설치에서 업데이트](USER_GUIDE_KO.md#기존-설치에서-업데이트)를 확인하세요.
이후 버전은 앱에서 새 버전을 알릴 수 있지만 다운로드·설치는 직접 진행합니다.

## Q35. macOS 구현과 이 Windows ZIP은 같은 배포판인가요?

별도 구현입니다. 공개 저장소의 .NET 8 macOS TUI/CLI는 실행 환경·패키징·검증 상태가 다릅니다.
Windows 2.5.0 ZIP은 macOS용이 아니며 scrcpy 5.0.1·702개 검증도 Windows 기준입니다.

2026-10-24 확인한 공개 릴리스에는 Windows ZIP이 있었고 Mac ZIP은 없었습니다.
소스·패키징 상태는 [macOS 가이드](https://github.com/maze-mei/DX-Manager/blob/main/docs/MACOS_GUIDE.md)를 따르세요.
