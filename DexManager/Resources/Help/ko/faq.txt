DX Manager 자주 묻는 질문

English FAQ · 한국어 사용 설명서

Q1. 휴대폰에 작은 화면(보조 디스플레이)이 남아 있습니다.

DX Manager가 강제 종료되었거나, 정리 명령을 보내기 전에 USB 또는 무선
연결이 완전히 끊기면 Android의 가상 디스플레이 설정이 남을 수 있습니다.
정상적으로 DX Manager를 종료하면 프로그램이 이 설정을 자동으로
제거합니다.

정상 종료할 때는 휴대폰을 연결한 상태에서 DeX 중지를 누르거나
Left Alt+F8을 누르거나, 시스템 트레이의 DX Manager 아이콘을 마우스 오른쪽
버튼으로 눌러 종료를 선택하십시오. 정리가 끝난 뒤 연결을 해제하십시오.

화면이 계속 남아 있다면 휴대폰에서 다음 순서로 제거할 수 있습니다.

1. 개발자 옵션을 엽니다.
2. 보조 디스플레이 시뮬레이션(Simulate secondary displays)을
   선택합니다.
3. 이미 없음이 선택되어 있어도 아무 해상도나 한 번 선택합니다.
4. 보조 디스플레이 시뮬레이션을 다시 열어 없음(None)을 선택합니다.

처음부터 없음만 선택하면 남은 화면이 지워지지 않을 수 있습니다. 해상도를
한 번 선택한 뒤 없음으로 바꾸면 Android가 overlay 설정을 새로 반영하고
남아 있던 가상 화면이 제거됩니다.

번들 공식 DX Companion을 설치하고 DX Manager의 설정 > 진단 > DX
Companion에서 검증과 권한 부여를 마쳤다면, 앱 본체나
빠른 설정 타일·홈 화면 위젯에서도 남은 화면을 제거할 수 있습니다. 비정상
종료 뒤 남은 개발자 옵션의 절전모드 해제도 끌 수 있습니다. 자세한
설치와 사용 방법은 한국어 사용 설명서를
참조하십시오.

Q2. 삼성 브라우저를 자동 실행할 때 선택 앱 강제 종료를 사용하는 이유는 무엇인가요?

삼성 브라우저가 휴대폰 화면에서 실행 중인 상태로 DeX 화면에 다시 열리면,
일부 환경에서 한영키 전환이 동작하지 않는 경우가 있습니다. 선택 앱 강제
종료를 켜면 기존 삼성 브라우저 프로세스를 휴대폰에서 먼저 종료한 뒤 DeX
화면에서 새로 실행하므로 이 문제를 피할 수 있습니다.

이 기능은 브라우저 데이터나 북마크를 삭제하지는 않지만, 저장하지 않은
입력 내용이나 진행 중인 작업은 사라질 수 있습니다. 다른 앱에서는 필요할
때만 사용하십시오.

Q3. 휴대폰을 두 대 이상 연결하면 어떤 기기를 사용하나요?

DX Manager 2.0은 여러 물리 휴대폰을 동시에 관리합니다. 두 대 이상이
감지되면 왼쪽 기기 목록에서 작업할 휴대폰을 선택하십시오. 각 휴대폰의
DeX·단일창·연결·Companion·파일 전송 상태가 독립적이므로 한 휴대폰을
시작하거나 분리해도 다른 휴대폰의 실행 세션을 교체하지 않습니다.

같은 물리 휴대폰의 USB와 무선 ADB 항목은 하나로 합쳐집니다. 그 휴대폰에
저장된 USB·Wi-Fi 정책에 따라 사용할 transport를 선택하며 반대 연결로
임의 전환하지 않습니다. 시작할 때 휴대폰이 한 대뿐이면 기기 목록을 숨기고,
두 번째 휴대폰이 확인되면 표시합니다.

Q4. 1600×900보다 낮은 해상도에서 DeX 화면 일부가 잘립니다.

Samsung DeX의 기본 최소 해상도는 1600×900입니다. DX Manager에서는 더
낮은 가상 해상도도 만들 수 있지만, 앱 서랍 상단이 잘리는 등 일부 DeX UI가
작은 화면에 맞게 배치되지 않을 수 있습니다.

앱 실행 자체에는 문제가 없을 수 있으나 전체 DeX UI를 정상적으로 사용하려면
1600×900 이상의 해상도를 권장합니다. 이 현상은 낮은 해상도에 대한 Samsung
DeX UI 제약이며 DX Manager가 화면 일부를 잘라내는 것은 아닙니다.

Q5. 해상도나 DPI를 바꾸니 바탕화면 아이콘과 배경화면이 달라졌습니다.

Samsung DeX는 해상도와 DPI 조합에 따라 화면 배율과 레이아웃 프로필을 다르게
판정할 수 있습니다. 같은 해상도에서도 DPI가 달라지면 아이콘 크기, 위젯
배치, 편집 가능 상태가 달라질 수 있으며 배경화면도 별도 상태로 관리될 수
있습니다.

따라서 설정을 바꾼 뒤 이전과 다른 바탕화면이 표시되어도 가상 디스플레이를
잘못 선택한 것은 아닐 수 있습니다. 자주 사용할 해상도와 DPI 조합을 정한
뒤 그 조합에서 바탕화면을 구성하는 것이 가장 안정적입니다.

Q6. 최근 앱 화면이 비정상적으로 보이고 데스크톱 1로 돌아갈 수 없습니다.

일부 해상도/DPI 조합에서는 DeX를 처음 실행한 뒤 최근 앱 화면의 데스크톱
표시가 어긋날 수 있습니다. 다음 방법으로 복구할 수 있습니다.

1. 최근 앱 화면에서 모니터 그림 안의 + 버튼을 눌러 새 데스크톱을
   만듭니다.
2. 화면 왼쪽에 일부 보이는 데스크톱 1을 선택합니다.

정상 화면으로 돌아오면 같은 DeX 세션에서는 대체로 다시 발생하지 않습니다.
Samsung 펌웨어나 One UI 버전에 따라 화면 구성과 명칭은 달라질 수 있습니다.

Q7. DPI를 120보다 낮게 설정할 수 없는 이유는 무엇인가요?

확인된 Samsung DeX 환경에서는 DPI 120이 가상 디스플레이를 생성할 수 있는
최솟값입니다. 119 이하에서는 overlay가 만들어지지 않아 새 display ID를
찾을 수 없습니다.

DX Manager는 120보다 작은 값이 입력되면 편집 전 값으로 되돌리고
안내합니다. 반대로 매우 높은 DPI는 생성되더라도 글자와 UI가 지나치게
커져 사용하기 어려울 수 있습니다.

Q8. 로그의 scrcpy-server 전송 속도가 평소보다 낮게 표시됩니다.

다음과 같은 줄은 scrcpy가 작은 scrcpy-server 파일을 휴대폰으로 전송할
때 계산한 순간 속도입니다.

text
scrcpy-server: 1 file pushed, 0 skipped. 42.9 MB/s


파일이 작고 전송 시간이 매우 짧아 수치 변동이 크며, 이 값이 USB 링크의
정확한 속도나 이후 영상 스트리밍 속도를 의미하지는 않습니다. 낮은 숫자만
표시됐다고 연결 오류로 판단할 필요는 없습니다.

다만 DeX 화면까지 버벅이거나 직접 scrcpy를 실행해도 계속 낮게 나온다면
데이터 전송을 지원하는 다른 USB 케이블과 PC의 다른 USB 포트를 시험해
보십시오. 충전 위주 케이블이나 품질이 낮은 케이블이 원인일 수 있습니다.

Q9. 무선 ADB 연결 또는 자동 재연결이 실패합니다.

다음 항목을 순서대로 확인하십시오.

- PC와 휴대폰이 서로 직접 통신할 수 있는 같은 로컬 네트워크인지 확인
- 게스트 Wi-Fi, AP/클라이언트 격리, VLAN과 회사 방화벽 확인
- 페어링 포트와 실제 연결 포트를 혼동하지 않았는지 확인
- 휴대폰 IP 주소가 바뀌지 않았는지 확인
- mDNS 자동 검색이 차단되면 페어링 포트가 아니라 무선 디버깅 화면의 현재
  연결 포트를 수동 입력
- 휴대폰 재부팅 후 USB로 무선 연결 준비를 다시 실행
- Android 11 이상 무선 디버깅은 필요하면 다시 페어링

무선 주소가 adb devices에 보이더라도 offline이면 연결을 끊었다가 다시
연결하십시오. 같은 Wi-Fi 이름을 사용한다는 사실만으로 기기 간 통신이
보장되지는 않습니다.

Q10. 장치 상태가 unauthorized 또는 offline으로 표시됩니다.

unauthorized는 PC의 ADB 키가 아직 휴대폰에서 승인되지 않았다는 뜻입니다.
휴대폰 화면을 켜고 RSA 디버깅 허용 창을 승인하십시오. 창이 나타나지 않으면
USB 디버깅 승인을 취소한 뒤 케이블을 다시 연결하거나 USB 디버깅을 껐다가
켜 보십시오.

offline은 장치 항목은 있지만 ADB 명령을 받을 수 없는 상태입니다. 케이블,
USB 포트, 무선 네트워크를 확인하고 연결을 다시 시도하십시오. USB 장치가
계속 나타나지 않으면 Samsung USB 드라이버와 보안 위험 자동 차단 설정도
확인하십시오.

Q11. 오른쪽 Shift를 왼쪽 Shift로 보정하는 이유는 무엇인가요?

Windows용 scrcpy 4.0/SDL3에서 Windows가 물리 오른쪽 Shift 입력을 정상적으로
감지해도 Android로 전달되지 않는 현상을 재현했습니다. scrcpy
3.3.4/SDL2에서는 같은 문제가 발생하지 않았습니다.

DX Manager는 SDL3 기반 scrcpy 4.x 클라이언트와의 호환을 위해 해당 scrcpy
창이 활성화된 동안에만 오른쪽 Shift 입력을 왼쪽 Shift로 바꿔 전달합니다.
일반적인 Shift 입력은 사용할 수 있지만 해당 세션의 Android 앱은 좌우
Shift를 구분할 수 없습니다. 다른 Windows 앱과 SDL2 기반 scrcpy에는 이
보정이 적용되지 않습니다.

Q12. 기기 연결 후 시작 대기와 프로세스 제한시간은 무엇이 다른가요?

기기 연결 후 시작 대기는 휴대폰 연결 상태와 기기 이름을 확인한 뒤,
DeX 또는 단일창의 실제 시작 명령을 보내기 전에 의도적으로 기다리는
시간입니다. 범위는 0~60초이고 기본값은 1초입니다. 0으로 설정하면 연결 확인
후 곧바로 시작합니다.

프로세스 제한시간은 ADB나 scrcpy 보조 프로세스가 응답하거나 창을 만들
때까지 기다릴 수 있는 최대 시간입니다. 명령이 정상적으로 빨리 끝나면 제한
시간 전체를 기다리지 않습니다. 느린 PC나 장치에서 시간 초과가 반복되는
경우가 아니라면 고급 옵션의 기본값을 바꿀 필요가 없습니다. 관리형 드래그 앤
드롭 파일 전송 전체에는 이 시간이 적용되지 않으며, 대용량 ADB push는 완료,
실패, 취소 또는 세션 종료까지 계속됩니다.

Q13. 사용 중 USB 연결이 갑자기 끊기면 어떻게 처리되나요?

DX Manager는 연결 해제를 확인하면 해당 휴대폰에서 실행하던 DeX와 단일창
세션을 정리합니다. 휴대폰이 사라져 즉시 보낼 수 없는 overlay, 화면 상태와
stay-awake 복구 명령은 같은 휴대폰이 다시 연결됐을 때 재시도할 수 있습니다.

원래 휴대폰이 다시 연결되면 설정된 시작 대기시간을 적용하고, 자동 실행이
켜져 있으면 세션을 다시 시작합니다. 다른 휴대폰이 연결되어 있어도 v1에서는
그 휴대폰으로 자동 전환하지 않습니다.

Q14. 휴대폰 화면 끄기와 잠자기 방지는 어떻게 다른가요?

폰 화면 끄기 (-S)는 scrcpy 세션을 실행하는 동안 실제 휴대폰 패널을
끄는 기능입니다. 휴대폰 화면이 꺼져도 DeX 가상 화면과 scrcpy 영상은 계속
동작합니다.

잠자기 방지는 세션 사용 중 Android가 잠들거나 연결을 중단하지 않도록
활성 상태를 유지합니다. 여러 DeX/단일창 세션 중 하나라도 화면 끄기 또는
잠자기 방지를 요청하면 DX Manager가 전체 세션 상태를 기준으로 관리합니다.
모든 관련 세션을 종료하거나 DX Manager를 정상 종료하면 휴대폰 화면과
stay-awake 상태의 복구를 시도합니다.

Q15. 휴대폰을 충전할 때 화면이 계속 켜져 있습니다.

DX Manager가 DeX 또는 단일창 사용 중 적용한 잠자기 방지 (-w) 설정은
세션이나 프로그램을 정상 종료하면 원래 상태로 복원됩니다.

다만 휴대폰 연결이 끊어진 상태에서 DX Manager를 종료했거나 프로그램이
비정상 종료된 경우에는 ADB 명령을 보낼 수 없어 설정을 복원하지 못할 수
있습니다. 이때는 다음 중 한 가지 방법으로 복구하십시오.

- 휴대폰의 개발자 옵션 → 절전모드 해제 항목을 직접 끕니다.
- 같은 휴대폰을 DX Manager에 다시 연결한 뒤 정상적인 방법으로 종료합니다.

이 설정은 USB 또는 충전기에 연결했을 때 화면이 자동으로 꺼지지 않게 할 수
있습니다.

Q16. Windows 7에서 무엇이 필요하며, DXManager.exe만 복사하면 왜 안 되나요?

DX Manager는 64비트 Windows 7 SP1과 .NET Framework 4.6.2 이상을
지원합니다. 32비트 Windows는 지원하지 않습니다. Windows 7/8.1에서는 번들
레거시 ADB 실행에 필요한 Universal CRT 업데이트와 Samsung USB 드라이버가
필요할 수 있습니다.

.NET Framework 4.6.2는 Windows 7 SP1에 기본 포함된 구성 요소가 아닙니다.
Windows 7 SP1 및 오프라인·폐쇄망 PC와의 호환성을 유지하기 위해 선택한 최소
대상 버전입니다. 설치되어 있지 않다면 Microsoft 공식 다운로드
페이지에서
런타임을 받으십시오. 같은 페이지의 오프라인 설치 파일을 다른 컴퓨터에서
받아 대상 PC로 옮겨 설치할 수도 있습니다.

.NET Framework 4.x는 제자리 업데이트 방식입니다. 4.7.2 또는 4.8이 이미
설치되어 있다면 4.6.2로 낮추거나 함께 설치하려고 할 필요가 없습니다. 같은
DX Manager 빌드가 설치된 최신 4.x 런타임에서 실행됩니다.

DXManager.exe는 다음 파일을 함께 사용하므로 실행 파일만 따로 복사하면
정상적으로 동작하지 않습니다.

- tools 아래 ADB와 scrcpy 실행 파일
- tools/adb-proxy 아래 DX Manager ADB 파일 전송 도우미
- scrcpy DLL과 scrcpy-server
- 한국어 리소스와 설정 파일
- 라이선스 및 제3자 고지 파일

배포 ZIP의 폴더 구조를 그대로 유지하고, 설정·로그·스크린샷을 저장할 수
있는 쓰기 가능한 위치에서 실행하십시오.

Q17. 드래그 앤 드롭 파일 전송은 어떻게 동작하며 끌 수도 있나요?

실행 중인 DeX 또는 단일창의 scrcpy 창에 파일을 하나 이상 놓거나 폴더 전체를
놓으십시오. 기본 DX Manager 파일 전송은 Windows 7 SP1부터 11까지 호환되는 경로로
한글·일본어 등 Unicode 이름을 보존합니다. 기본 저장 위치는
/sdcard/Download/이며 설정 > 경로 / ADB > 프로그램 및 저장 경로에서
바꿀 수 있습니다. 저장 위치는 /sdcard/ 또는 /storage/emulated/0/ 아래
폴더만 지정할 수 있습니다.

폴더는 최상위 폴더, 하위 폴더, 파일과 빈 폴더를 보존합니다. 정션, 심볼릭
링크 등 재분석 지점은 건너뜁니다. APK 파일을 단독으로 놓으면 scrcpy의 설치
동작을 유지하고, 폴더 안에 포함된 APK는 일반 파일로 복사합니다.

독립적으로 이동할 수 있는 상태창에는 현재 전송 항목과 다음 대기 항목 4개,
파일 크기, 경과 시간, 완료·실패·대기 수와 취소 버튼이 표시됩니다. 지원하는
모든 Windows와 ADB 조합에서 정확한 전송 바이트를 얻을 수 없으므로 진행률과
남은 시간은 표시하지 않습니다.

휴대폰의 기존 파일과 폴더는 덮어쓰지 않습니다. 같은 이름이 있으면
이름 (1).확장자, 이름 (2).확장자 또는 폴더 (1)로 저장합니다. 취소하면
해당 scrcpy 창의 진행 중·대기 중 전송을 모두 중단하고 휴대폰의 임시 데이터도
제거하도록 시도합니다. 최종 이름을 확정하는 짧은 동안에는 버튼이 비활성화됩니다.

scrcpy의 순정 파일 드롭 방식을 사용하려면 설정 > 경로 / ADB > 프로그램 및
저장 경로에서 DX Manager 파일 전송 사용 (한글/Unicode 호환)을
끄십시오. 변경은 새로 여는 DeX와 단일창부터 적용되며 이미 열린 창은 시작할
때 선택된 방식을 유지합니다. 순정 scrcpy 방식은 일부 Windows 환경에서
비ASCII 파일명을 보존하지 못할 수 있습니다.

Q18. 이전 One UI 버전에서 DeX 창이 검게 표시됩니다.

현재 정상 동작을 확인한 기준은 Android 16 / One UI 8.x가 설치된 DeX 지원
Galaxy 기기입니다. One UI 7.x 이하에서는 DX Manager의 가상 디스플레이
방식을 원활하게 사용할 수 있는지 확인되지 않았으며 검은 DeX 창이 열릴 수
있습니다. 기기 모델, Samsung 펌웨어와 예전 클래식 DeX 구현 사용 여부에 따라
동작이 달라질 수 있습니다.

단일창은 scrcpy 자체 가상 디스플레이를 사용하므로 동작할 수 있지만 펌웨어에
따라 입력 지원이 다를 수 있습니다. HID 키보드나 HID 마우스 사용 시 불안정한
경우 해당 옵션을 끄고 다시 시험할 수 있습니다. 이 방법이 해당 기기나 One UI
버전의 지원을 보장하는 것은 아닙니다.

Q19. ADB 버전이 항상 1.0.41로 보였는데 실제 사용 버전은 무엇인가요?

Android Debug Bridge version 1.0.41은 여러 platform-tools 릴리스가 공통으로
출력하는 ADB 프로토콜 문구이며 실제 실행 파일의 빌드 버전이 아닙니다.

DX Manager 1.1.0 이상은 그 다음 Version ... 줄을 읽습니다. 번들 scrcpy ADB는
37.0.0-14910828, Windows 7/8.1용 레거시 ADB는 34.0.1-9979309로
표시됩니다. 수동으로 ADB를 선택하면 해당 실행 파일의 Version ... 값이
표시됩니다.

Q20. 금융·게임 앱이 실행되지 않거나 화면이 검게 표시됩니다.

일부 금융·게임·스트리밍·보안 앱은 USB 디버깅이나 개발자 옵션이 켜진 환경을
감지해 실행을 거부할 수 있습니다. 보안 화면 또는 DRM 콘텐츠의 캡처·미러링을
차단하거나 가상·보조 디스플레이에서의 실행을 허용하지 않는 앱도 있습니다.

이는 해당 앱과 Android의 보안 정책에 따른 동작입니다. DX Manager는 이러한
보안 제한을 우회하지 않습니다.

Q21. DeX에서 실행한 앱이 휴대폰 화면에서 열립니다.

일부 앱은 다중 디스플레이를 완전히 지원하지 않거나 휴대폰에서 이미 실행 중인
인스턴스를 다시 사용합니다. 휴대폰에서 해당 앱을 완전히 종료한 뒤 DeX에서
다시 실행하거나 DX Manager의 선택 앱 강제 종료 옵션을 사용해 보십시오.

그래도 휴대폰에서 열린다면 해당 앱이 보조 디스플레이 실행을 제대로 지원하지
않는 경우일 수 있으며 DX Manager에서 강제로 변경하지 못할 수 있습니다.

Q22. 마우스가 DeX 창 밖으로 나오지 않습니다.

HID 마우스 (-M)를 켜면 scrcpy가 마우스를 Android에 직접 연결된 입력
장치처럼 전달하므로 포인터가 scrcpy 창에 캡처됩니다. 왼쪽 Alt를 눌러 캡처를
일시적으로 해제하거나 다시 활성화할 수 있습니다.

Windows와 DeX 사이에서 포인터를 항상 자유롭게 이동하려면 HID 마우스를 끄고
DeX 또는 단일창을 다시 여십시오. 이 경우 마우스가 일반 하드웨어 마우스가
아닌 터치 입력에 가깝게 동작하므로, 측면 버튼이 최근 앱을 열거나 왼쪽 버튼을
길게 누르는 동작이 화면 롱터치로 처리되는 등 조작 방식이 달라질 수 있습니다.

Q23. 진단 메뉴의 정리 앱 권한 부여 버튼이 비활성화되어 있습니다.

권한 부여 버튼은 공식 DX Companion이 선택된 휴대폰에 설치되어 있고
APK 서명 인증서까지 일치할 때만 활성화됩니다. 앱이 없으면 DX Companion
설치를 사용할 수 있으며, 번들 APK가 없거나 변경된 경우 설치 버튼도
비활성화됩니다. 휴대폰이 ADB로 승인되지 않았거나 같은 패키지명의 다른 서명
앱이면 권한을 부여하지 않습니다. 버튼 아래의 상태 설명을 확인하십시오.

활성화된 정리 앱 권한 부여를 누르면 DX Manager가 앱을 다시 검증한 뒤
WRITE_SECURE_SETTINGS 권한을 부여하고 실제 권한 상태를 재확인합니다. 완료
후에는 권한 부여됨으로 표시됩니다. 정리 앱에는 임의의 ADB 명령을 실행하는
기능이 없습니다.

권한은 재부팅하거나 같은 공식 서명의 APK로 업데이트해도 유지됩니다. 앱을
삭제한 뒤 새로 설치하면 권한도 삭제되므로 다시 부여해야 합니다. 권한 부여 후
앱 본체에서는 가상화면 제거, 절전모드 해제 끄기 또는 둘 다를 실행할 수
있습니다. 빠른 설정 타일과 2 × 1 위젯은 기본적으로 둘 다 정리하며 앱에서
정리 범위를 바꿀 수 있습니다.

정리 앱을 사용하지 않는 경우에도 휴대폰의 개발자 옵션 → 보조 디스플레이
시뮬레이션에서 아무 해상도나 한 번 선택한 뒤 다시 없음을 선택하면 남은
화면을 제거할 수 있습니다.

Q24. DX Companion에서 파일 또는 폴더를 PC로 보낼 수 없습니다.

DX Manager를 먼저 실행하고 전송 대상 휴대폰을 USB 또는 무선 ADB로 연결한 뒤,
DX Companion의 파일 전송 탭에 수신 준비 안내가 표시되는지 확인하십시오.
준비 안내가 없다면 DX Manager의 설정 > 진단 > DX Companion에서 설치 버전,
공식 서명과 권한 상태를 확인하고 연결을 다시 시도하십시오.

일반 파일은 갤러리나 내 파일의 공유 메뉴에서 DX Manager로 보내기를
선택합니다. Android 공유 메뉴는 폴더 자체를 전달하지 않으므로 폴더는 DX
Companion 앱의 폴더 보내기 > 폴더 선택을 사용해야 합니다.

PC 저장 위치는 설정 > 경로 / ADB > 휴대폰→PC 저장 폴더에서 바꿀 수
있습니다. 같은 이름의 항목이 이미 있으면 덮어쓰지 않고 (1), (2) 접미사를
붙입니다. 전송 중 연결이 끊기면 실패로 처리하며, 다시 연결한 뒤 전송을 새로
시작하십시오.
